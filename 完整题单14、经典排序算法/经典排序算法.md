## 排序算法总览

| 算法 | 平均 | 最好 | 最坏 | 额外空间 | 稳定性 | 原地 |
|---|---|---|---|---|---|---|
| 冒泡排序 | O(n²) | O(n) | O(n²) | O(1) | 稳定 | 是 |
| 选择排序 | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 | 是 |
| 插入排序 | O(n²) | O(n) | O(n²) | O(1) | 稳定 | 是 |
| 希尔排序 | O(n^1.3) | O(n log n) | O(n²) | O(1) | 不稳定 | 是 |
| 快速排序 | O(n log n) | O(n log n) | O(n²) | O(log n) | 不稳定 | 是 |
| 归并排序 | O(n log n) | O(n log n) | O(n log n) | O(n) | 稳定 | 否 |
| 堆排序 | O(n log n) | O(n log n) | O(n log n) | O(1) | 不稳定 | 是 |
| 计数排序 | O(n + k) | O(n + k) | O(n + k) | O(k) | 稳定 | 否 |
| 桶排序 | O(n + k) | O(n) | O(n²) | O(n + k) | 稳定 | 否 |
| 基数排序 | O(d(n + k)) | O(d(n + k)) | O(d(n + k)) | O(n + k) | 稳定 | 否 |

> 选型口诀：
> 通用首选快排，要求稳定用归并，空间紧张用堆排；  
> 小数组（n < 16）一律插入排序；  
> 值域 k 很小用计数排序，数据均匀用桶排序，定长整数用基数排序；  
> 工程里直接用 `std::sort`（内省排序），要稳定用 `std::stable_sort`（归并）。  
>
> 注意：前七种是**比较排序**，下界是 Ω(n log n)；后三种是**非比较排序**，靠「值」而不是「比较」定位，才能突破这个下界。

## No.0 基础排序

这三种都是 O(n²)，只适合 n 很小或近乎有序的场景。共同点是思路直白、代码短，面试里常作为「你能优化到多少」的起点。

### 一：冒泡排序

> 相邻两两比较，大的往后冒。每一轮把当前未排序部分的最大值送到末尾。  
> 两个优化：  
> ① 本轮没有发生任何交换，说明已经有序，直接退出；  
> ② 记录本轮最后一次交换的位置，它右边的元素都已经就位，下一轮不用再扫。

```cpp
void bubbleSort(vector<int>& a) {
    int n = a.size();
    int end = n - 1;                 // 本轮冒泡的终点
    while (end > 0) {
        int lastSwap = -1;           // 本轮最后一次交换的位置
        for (int i = 0; i < end; i++) {
            if (a[i] > a[i + 1]) {
                swap(a[i], a[i + 1]);
                lastSwap = i;
            }
        }
        if (lastSwap < 0) break;     // 一次都没换，已经有序
        end = lastSwap;              // lastSwap 之后都已就位
    }
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间 | 稳定性 |
|---|---|---|
| O(n²) / O(n) / O(n²) | O(1) | 稳定 |

**为什么稳定**：只在 `a[i] > a[i + 1]` 时交换，相等不换，相同元素的相对顺序不会被破坏。

**为什么最好能到 O(n)**：完全有序时第一轮 `lastSwap` 就是 -1，直接 break，只扫一遍。

### 二：选择排序

> 每一轮从未排序区间里挑出最小值，和区间首元素交换。  
> 交换次数固定最多 n-1 次，是所有排序里**交换次数最少**的 —— 当「交换」本身很贵时（比如元素很大、要动磁盘）有意义。

```cpp
void selectSort(vector<int>& a) {
    int n = a.size();
    for (int i = 0; i < n - 1; i++) {
        int minIdx = i;
        for (int j = i + 1; j < n; j++) {
            if (a[j] < a[minIdx]) minIdx = j;
        }
        if (minIdx != i) swap(a[i], a[minIdx]);
    }
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间 | 稳定性 |
|---|---|---|
| O(n²) / O(n²) / O(n²) | O(1) | 不稳定 |

**为什么不稳定**：把最小值换到最前面时，位置 `i` 上的元素会被「扔」到远处，跨过中间与它相等的元素。  
例：`[5a, 5b, 3]` → 第一轮最小值 3 和 5a 交换 → `[3, 5b, 5a]`，5a 被扔到了 5b 后面。  
第二轮比较 5b 和 5a 时，因为两者相等（`a[j] < a[mn]` 为 false）不会交换，这个错误顺序就**固定下来了**，不会自我修复。

**为什么最好也是 O(n²)**：它无论如何都要把每轮的剩余区间完整扫一遍，没有任何提前退出的依据。

### 三：插入排序

> 就像摸扑克牌，把第 i 张牌插到前面已经有序的牌里。  
> 它是**唯一在实际工程中真被用到的 O(n²) 排序** —— `std::sort` 在区间长度小于 16 时就会切到插入排序。

```cpp
void insertSort(vector<int>& a) {
    int n = a.size();
    for (int i = 1; i < n; i++) {
        int key = a[i];
        int j = i - 1;
        while (j >= 0 && a[j] > key) {   // 必须是 >，写 >= 就不稳定
            a[j + 1] = a[j];             // 挪位而不是交换，少一半赋值
            j--;
        }
        a[j + 1] = key;
    }
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间 | 稳定性 |
|---|---|---|
| O(n²) / O(n) / O(n²) | O(1) | 稳定 |

**为什么稳定**：内层条件是 `a[j] > key`，遇到相等的就停下来，`key` 插在它后面，相同元素顺序不变。

**为什么用挪位不用交换**：交换一次要 3 次赋值（`swap`），挪位只要 1 次。插入排序的「移动」总量相同，但常数小一倍。

**为什么最好 O(n)**：完全有序时内层 while 一次都不进，外层只走 n 次。

## No.1 进阶排序

四种 O(n log n)（希尔最坏会退到 O(n²)）。面试手写重点是**快排**和**归并**，堆排要会写 `siftDown`。

### 四：快速排序

> 选一个基准 pivot，把区间分成「小于基准」和「大于基准」两半，再递归处理两半。  
> 核心是**分区**。这里用 Hoare 双指针写法：i 从左边找 ≥ pivot 的，j 从右边找 ≤ pivot 的，交换后继续向中间收缩。  
> 相比单指针的 Lomuto 分区，Hoare 写法对**大量重复元素**更友好（相等的会被均分到两侧，不会全堆到一边退化成 O(n²)）。

```cpp
void quickSort(vector<int>& a, int l, int r) {
    if (l >= r) return;
    int i = l, j = r;
    int pivot = a[l + (r - l) / 2];   // 取中间元素做基准，已有序的数据也不会退化

    while (i <= j) {
        while (a[i] < pivot) i++;     // 从左找 >= pivot 的
        while (a[j] > pivot) j--;     // 从右找 <= pivot 的
        if (i <= j) {
            swap(a[i], a[j]);
            i++;
            j--;
        }
    }
    // 此时 [l, j] 全部 <= pivot，[i, r] 全部 >= pivot
    quickSort(a, l, j);
    quickSort(a, i, r);
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间（递归栈） | 稳定性 |
|---|---|---|
| O(n log n) / O(n log n) / O(n²) | O(log n) / O(n) | 不稳定 |

**为什么不稳定**：i、j 从两端向中间交换，等于 pivot 的元素同样会被换走，相对顺序就被打乱了。  
极端例子：`[3a, 3b, 3c]`（三个元素全相等）第一轮就执行 `swap(a[0], a[2])`，直接变成 `[3c, 3b, 3a]`，顺序完全反转。  
这也正是三路划分版更快的原因 —— 它把所有等于 pivot 的元素聚到中间，一次就整段跳过。

**最坏 O(n²) 什么时候发生**：每次分区都极不均衡（比如固定取首元素当基准，而数据本身已有序）。取中间元素、随机化、三数取中都能避免这种退化。

**三路划分版（大量重复元素时更快）**：把区间切成「< pivot | == pivot | > pivot」三段，等于 pivot 的部分直接跳过不递归。

```cpp
void quickSort3Way(vector<int>& a, int l, int r) {
    if (l >= r) return;
    int pivot = a[l + (r - l) / 2];
    int lt = l, gt = r, i = l;        // [l,lt) < pivot, [lt,i) == pivot, (gt,r] > pivot

    while (i <= gt) {
        if (a[i] < pivot)      swap(a[lt++], a[i++]);
        else if (a[i] > pivot) swap(a[gt--], a[i]);   // 换过来的还没判，i 不动
        else                   i++;
    }
    quickSort3Way(a, l, lt - 1);
    quickSort3Way(a, gt + 1, r);
}
```

**快速选择（求第 k 小，平均 O(n)）**：只递归包含目标的那一半，另一半直接扔掉。

```cpp
// 返回第 k 小的元素，k 从 0 开始计数
int quickSelect(vector<int>& a, int k) {
    int l = 0, r = (int)a.size() - 1;
    while (true) {
        if (l >= r) return a[l];
        int i = l, j = r;
        int pivot = a[l + (r - l) / 2];

        while (i <= j) {
            while (a[i] < pivot) i++;
            while (a[j] > pivot) j--;
            if (i <= j) {
                swap(a[i], a[j]);
                i++;
                j--;
            }
        }
        if (k <= j)      r = j;          // 目标在左半
        else if (k >= i) l = i;          // 目标在右半
        else             return a[k];    // 夹在中间，这一整段都等于 pivot
    }
}
```

### 五：归并排序

> 先递归把左右两半排好，再把两个有序数组合并成一个。  
> 它是**唯一稳定且 O(n log n)** 的原地外排序方案，代价是需要 O(n) 辅助数组。  
> 顺带能拿到**逆序对数量** —— 这是快排做不到的，面试高频。

```cpp
// tmp 是长度 n 的辅助数组，所有递归层共用
void mergeSort(vector<int>& a, int l, int r, vector<int>& tmp) {
    if (l >= r) return;
    int mid = l + (r - l) / 2;
    mergeSort(a, l, mid, tmp);
    mergeSort(a, mid + 1, r, tmp);

    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        // 必须 <=，相等时优先取左边，才能保证稳定
        tmp[k++] = (a[i] <= a[j]) ? a[i++] : a[j++];
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r)   tmp[k++] = a[j++];
    for (int t = l; t <= r; t++) a[t] = tmp[t];
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间 | 稳定性 |
|---|---|---|
| O(n log n) / O(n log n) / O(n log n) | O(n) | 稳定 |

**为什么最好最坏都是 O(n log n)**：不管数据长什么样，它都严格二分到叶子再逐层合并，每层总代价 O(n)，共 log n 层。

**为什么稳定**：合并时用 `a[i] <= a[j]` 取左边，相等的两个元素里左边的先进结果，相对顺序不变。

**求逆序对**：当 `a[j] < a[i]` 时，左边 `a[i..mid]` 这 `mid - i + 1` 个元素都大于 `a[j]`，全构成逆序对。

```cpp
// 返回逆序对总数，结果可能超 int，用 long long
long long mergeCount(vector<int>& a, int l, int r, vector<int>& tmp) {
    if (l >= r) return 0;
    int mid = l + (r - l) / 2;
    long long cnt = mergeCount(a, l, mid, tmp) + mergeCount(a, mid + 1, r, tmp);

    int i = l, j = mid + 1, k = l;
    while (i <= mid && j <= r) {
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];
        } else {
            tmp[k++] = a[j++];
            cnt += mid - i + 1;      // 左边剩下的全都大于 a[j]
        }
    }
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= r)   tmp[k++] = a[j++];
    for (int t = l; t <= r; t++) a[t] = tmp[t];
    return cnt;
}
```

### 六：堆排序

> 先建大顶堆（从最后一个非叶结点往前做 `siftDown`），然后反复把堆顶换到末尾、缩小堆、重新下沉。  
> 优点：**O(1) 额外空间 + 最坏也保证 O(n log n)**，没有任何退化风险。  
> 确定的是缓存不友好（跳着访问），实际比快排慢 2~3 倍。

```cpp
// 让 a[i] 在 [0, n) 这个堆里下沉到正确位置
void siftDown(vector<int>& a, int i, int n) {
    while (true) {
        int l = i * 2 + 1, r = l + 1, best = i;
        if (l < n && a[l] > a[best]) best = l;
        if (r < n && a[r] > a[best]) best = r;
        if (best == i) break;        // 已经比两个孩子都大，停
        swap(a[i], a[best]);
        i = best;
    }
}

void heapSort(vector<int>& a) {
    int n = a.size();
    // 建堆：从最后一个非叶结点 n/2-1 往前，自底向上下沉
    for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n);

    // 依次把堆顶（最大值）换到末尾
    for (int end = n - 1; end > 0; end--) {
        swap(a[0], a[end]);
        siftDown(a, 0, end);         // 剩余 end 个元素重新成为堆
    }
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间 | 稳定性 |
|---|---|---|
| O(n log n) / O(n log n) / O(n log n) | O(1) | 不稳定 |

**为什么是 O(n log n) 而不是 O(n²)**：`siftDown` 每次最多走树高 log n 层，调用 n 次。

**建堆为什么是 O(n) 而不是 O(n log n)**：越靠下的结点越多，但它们能下沉的层数越少，加权求和后是 O(n)。这个结论面试常问。

**为什么不稳定**：建堆和交换都是远距离跳跃，相同元素的相对位置会被打乱。  
例：`[3a, 3b, 3c]` 建堆时不动，但随后两次「堆顶换到末尾」会变成 `[3b, 3c, 3a]`。

### 七：希尔排序

> 插入排序的改进版：先按较大的间隔 gap 做插入排序，让元素大致有序，再逐步缩小 gap，最后 gap=1 时做一次普通插入排序。  
> 前面几轮把「远距离的小元素」快速挪到前面，最后一轮插入排序就不用再移动太多。

```cpp
void shellSort(vector<int>& a) {
    int n = a.size();
    for (int gap = n / 2; gap > 0; gap /= 2) {
        // 对每个间隔 gap 的子序列做插入排序
        for (int i = gap; i < n; i++) {
            int key = a[i];
            int j = i - gap;
            while (j >= 0 && a[j] > key) {
                a[j + gap] = a[j];
                j -= gap;
            }
            a[j + gap] = key;
        }
    }
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间 | 稳定性 |
|---|---|---|
| O(n^1.3) / O(n log n) / O(n²) | O(1) | 不稳定 |

**复杂度为什么说不准**：希尔排序的复杂度**取决于 gap 序列的取法**。`gap = n/2, n/4, ...` 这个序列的最坏情况是 O(n²)（可以构造出反例）；换成 Hibbard 序列 `2^k - 1` 最坏 O(n^1.5)，Sedgewick 序列能到 O(n^1.33)。这里是常见教学写法。

**为什么不稳定**：gap > 1 时的「跳跃式插入」会让相同元素互相跨过。  
例：`[2a, 1b, 1c, 1d]`（n = 4，gap = 2）第一轮把 1c 换到最前面，最终结果是 `[1c, 1b, 1d, 2a]`，三个 1 的顺序乱了。

## No.2 线性排序

这三类**不靠比较**，靠元素的值直接算出该放哪，所以能突破 Ω(n log n) 下界。代价是对数据有额外要求（值域有限、均匀分布、定长整数）。

### 八：计数排序

> 统计每个值出现了几次，再求前缀和确定每个值在结果数组里的「结束位置」，最后倒序回填。  
> 倒序回填是为了**保证稳定** —— 从后往前放，相同值的元素顺序才和原数组一致。

```cpp
void countingSort(vector<int>& a) {
    if (a.empty()) return;
    int mn = *min_element(a.begin(), a.end());
    int mx = *max_element(a.begin(), a.end());

    vector<int> cnt(mx - mn + 1, 0);
    for (int x : a) cnt[x - mn]++;                    // 1. 计数

    for (int i = 1; i < (int)cnt.size(); i++) cnt[i] += cnt[i - 1];   // 2. 前缀和

    vector<int> out(a.size());
    for (int i = (int)a.size() - 1; i >= 0; i--) {    // 3. 倒序回填
        out[--cnt[a[i] - mn]] = a[i];
    }
    a = out;
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间 | 稳定性 |
|---|---|---|
| O(n + k) / O(n + k) / O(n + k) | O(k) | 稳定 |

k = 值域大小 `mx - mn + 1`。

**为什么能做到 O(n + k)**：没有任何比较，只用了「数组下标」这个 O(1) 的定位手段。

**什么时候不能用**：k 远大于 n 时。比如 n = 10⁵、值域 10⁹，光开计数数组就要 4GB。这时要么用基数排序拆位，要么换回比较排序。

**为什么倒序回填**：前缀和算出来的是「该值应放的最后一个位置 + 1」。从后往前遍历原数组，遇到相同值时依次放到递减的位置，先出现的就落在靠前的位置 → 稳定。

### 九：桶排序

> 把值域均分成 k 个桶，每个元素按「值落在哪个桶」丢进去，桶内各自排序，最后按桶顺序拼接。  
> 它是计数排序的推广：计数排序每个桶只装一个值，桶排序一个桶装一段值。

```cpp
void bucketSort(vector<int>& a) {
    if (a.empty()) return;
    int n = a.size();
    int mn = *min_element(a.begin(), a.end());
    int mx = *max_element(a.begin(), a.end());
    if (mn == mx) return;

    int bucketCnt = max(1, (int)sqrt(n));             // 桶数取 √n 是常用经验值
    double width = double(mx - mn + 1) / bucketCnt;   // 每个桶覆盖的值域宽度

    vector<vector<int>> buckets(bucketCnt);
    for (int x : a) {
        int idx = min(bucketCnt - 1, (int)((x - mn) / width));
        buckets[idx].push_back(x);
    }

    int k = 0;
    for (auto& b : buckets) {
        sort(b.begin(), b.end());                     // 桶内排序
        for (int x : b) a[k++] = x;
    }
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间 | 稳定性 |
|---|---|---|
| O(n + k) / O(n) / O(n²) | O(n + k) | 稳定 |

**为什么最坏会到 O(n²)**：所有元素都落进同一个桶，退化成对这个桶做一次普通排序。数据必须**均匀分布**，桶排序才有优势。

**`idx` 为什么要 `min(bucketCnt - 1, ...)`**：最大值 `x == mx` 时算出来的下标正好等于 `bucketCnt`，会越界。

### 十：基数排序

> 从最低位到最高位，每一位做一次**稳定的计数排序**。  
> 因为每一轮都是稳定排序，低位排好的相对顺序会被高位保留下来，跑完最高位整个数组就有序了。

```cpp
void radixSort(vector<int>& a) {
    if (a.empty()) return;

    // 按位取模对负数会得到负下标，先把整个数组平移到非负区间
    int mn = *min_element(a.begin(), a.end());
    int mx = *max_element(a.begin(), a.end());
    int offset = (mn < 0) ? -mn : 0;
    int maxVal = mx + offset;

    vector<int> tmp(a.size());
    for (int exp = 1; maxVal / exp > 0; exp *= 10) {   // exp = 1, 10, 100, ...
        int cnt[10] = {0};
        for (int x : a) cnt[((x + offset) / exp) % 10]++;     // 统计当前位
        for (int i = 1; i < 10; i++) cnt[i] += cnt[i - 1];

        for (int i = (int)a.size() - 1; i >= 0; i--) {        // 倒序保证稳定
            int d = ((a[i] + offset) / exp) % 10;
            tmp[--cnt[d]] = a[i];
        }
        a = tmp;
    }
}
```

| 时间（平均 / 最好 / 最坏） | 额外空间 | 稳定性 |
|---|---|---|
| O(d(n + k)) / O(d(n + k)) / O(d(n + k)) | O(n + k) | 稳定 |

d = 最大值的位数，k = 进制（这里是 10）。

**为什么必须用稳定排序做每一轮**：上一轮已经按低位排好了，这一轮按高位排时，如果相同高位的元素相对顺序被打乱，低位的成果就白排了。

**为什么要加 offset**：`(x / exp) % 10` 在 x 为负时结果是负的，直接拿去当 `cnt` 的下标会越界崩溃。整体加上 `-min` 之后所有元素都变成非负数，按位取模就正常了，排序完再原样输出（偏移是加在取位时，没有修改数组本身的值）。

**注意溢出**：`x + offset` 在 `x` 接近 `INT_MIN` 时会溢出。真要处理这种极端值域，改用 `long long` 或者把正负数拆成两组分别排序。

## No.3 工程实践

### 十一：sort 用法与比较器

```cpp
vector<int> a = {3, 1, 4, 1, 5};

sort(a.begin(), a.end());                              // 升序
sort(a.begin(), a.end(), greater<int>());              // 降序
sort(a.begin(), a.end(), [](int x, int y) {
    return x > y;                                      // 自定义：降序
});

// 结构体多关键字排序
struct Node { int id; int score; };
vector<Node> v;
sort(v.begin(), v.end(), [](const Node& A, const Node& B) {
    if (A.score != B.score) return A.score > B.score;  // 分数高的在前
    return A.id < B.id;                                // 同分按 id 升序
});
```

**比较器必须是严格弱序**，三条硬性要求：

1. `cmp(x, x)` 必须返回 **false**（不能自己小于自己）
2. `cmp(x, y)` 和 `cmp(y, x)` 不能同时为 true
3. 可传递：`cmp(x,y) && cmp(y,z)` 推出 `cmp(x,z)`

写成 `return A.score >= B.score;` 就违反了第 1 条 —— 这是**未定义行为**，在 libstdc++ 上实测会出现越界访问或死循环，而且不是每次都崩，极难调试。

### 十二：std::sort 为什么快

`std::sort` 用的不是纯快排，而是**内省排序（introsort）**，三种算法混合：

1. **主算法快排** —— 平均常数最小、缓存友好
2. **递归深度超过 `2 * log2(n)` 时切换到堆排序** —— 把最坏情况从 O(n²) 拉回 O(n log n)
3. **区间长度小于 16 时切换到插入排序** —— 小数组上插入排序比快排快（没有递归开销，且挪位常数小）

所以 `std::sort` 保证了 **O(n log n) 的最坏复杂度**，这是它比手写快排可靠的关键。

`std::stable_sort` 用的是归并排序（内存够时用类似 TimSort 的优化版），保证稳定，代价是 O(n) 的额外空间。

### 十三：手写排序的常见坑

| 坑 | 说明 |
|---|---|
| 比较器写成 `>=` | 违反严格弱序，`std::sort` 里是 UB，可能死循环或越界 |
| 快排递归深度 O(n) | 数据有序 + 基准取端点时栈会爆（n = 10⁵ 就危险），要随机化/三数取中，或小区间切插入排序 |
| Lomuto 分区遇到全相同元素 | 全相等时每次只切掉一个元素，退化 O(n²)。用 Hoare 或三路划分 |
| `mid = (l + r) / 2` 溢出 | l、r 都接近 `INT_MAX` 时会溢出成负数，写 `l + (r - l) / 2` |
| 归并忘记回写 | 合并完 `tmp` 后必须 `a[t] = tmp[t]` 搬回原数组，否则前面的递归全白做 |
| 归并的 `tmp` 每层都 new | 应该在最外层开一次、所有递归层共用，否则时间空间都翻倍 |
| 计数排序值域过大 | n 小但值域 10⁹ 时，开计数数组直接爆内存 |
| 基数排序直接对负数取位 | `(x / exp) % 10` 得到负下标，拿去索引 `cnt` 直接越界崩溃，必须先整体加偏移平移 |
| 排序后还要用原下标 | `sort` 会打乱下标，需要「带下标的元素」一起排序（`pair<值, 原下标>`） |
| 要稳定却用了 `sort` | `sort` 不稳定，改 `stable_sort`，或者把原下标作为第二关键字 |
